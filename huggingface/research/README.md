# Research

The exploration that the design in `CONVENTIONS.md` and `datasets/opendata/` is based on: one
question per script, each writing a report to `reports/`. Kept as evidence and frozen; production
code does not import from here (`lib/` is a snapshot of what became `datasets/opendata/`).

Every script is a standalone [PEP 723](https://peps.python.org/pep-0723/) script with inline
dependencies. Run them from `huggingface/` with `uv run <script>`; no virtualenv or
`pyproject.toml` is needed.

```
research/
├── lib/
│   └── gcod.py                     shared helpers: paths, zip reading (no extraction),
│                                   canonical time-series schema, ride↔CSV matching, report utils
├── explore/                        one question per script, numbered in run order
│   ├── 01_osf_listing.py           full OSF file listing (+ sha256) → data/osf/listing.parquet
│   ├── 02_download_sample.py       stratified sample (size decile × upload year) → data/osf/athletes/
│   ├── 03_profile_timeseries.py    CSV headers, types, decimals, sampling, gaps
│   ├── 04_profile_metadata.py      JSON keys, metrics, sports, ride↔CSV matching
│   ├── 05_benchmark_encodings.py   Parquet encodings: size / speed / exactness
│   ├── 06_benchmark_layouts.py     per-athlete files vs shards, read amplification
│   ├── 07_prototype_metadata_tables.py   `activities` / `athletes` tables from JSON
│   ├── 08_build_prototype_repo.py  end-to-end dry run: HF repo folder from the sample + load test
│   ├── 09_precision_census.py      significant digits of every CSV value; float32 round trip
│   ├── 10_benchmark_columns.py     per-column representations (f64/f32/metres/int units)
│   └── 11_benchmark_distance_delta.py  cumulative vs per-sample distance
├── share/
│   └── gcod_parquet.py             self-contained script for collaborators: raw zip → opendata
│                                   layout, with an exactness check
├── reports/                        generated findings
└── README.md
```

Conventions

- Paths come from `research/lib/gcod.py` (`data/` for inputs and intermediates, `research/reports/` for output).
- Every explore script writes a markdown report to `research/reports/NN_<name>.md`. Machine-readable
  intermediates go to `data/interim/`.
- Downloaded zips are untrusted input: they are read member by member and never extracted.
- `data/` is git-ignored; everything in it can be regenerated by running the scripts in order.

Run everything:

```bash
uv run research/explore/01_osf_listing.py
uv run research/explore/02_download_sample.py          # ~3 GB, ~1 MB/s from OSF
for s in 03 04 05 06 07 08 09 10 11; do uv run research/explore/${s}_*.py; done
```
